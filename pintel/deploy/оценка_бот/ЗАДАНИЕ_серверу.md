# Задание: поставить приём оценки с точки в тестового бота

Это задание для чата, у которого есть доступ к серверу Pintel. Всё — только в тестовом
контуре: тестовый бот `PintelOlxBot` и база `pintel_ocenka_test`. Рабочий бот Оценки не
трогаем вовсе.

## Что происходит и зачем

Приложение на точке (Pintel Diagnostics, exe) проверяет iPhone по кабелю и должно создавать
сделку в Оценке. **Порт Postgres Оценки закрыт наружу**, своего сервера мы не держим,
поэтому в базу с точки хода нет. Канал остаётся один — Telegram, и сделку создаёт сам
бот: он на сервере, база у него под рукой.

Как это работает:

1. Приложение показывает QR со ссылкой `https://t.me/PintelOlxBot?start=p<КОД>`.
   Сотрудник открывает её своим телефоном, бот узнаёт его по `chat_id` — это и есть
   оценщик сделки. Дальше бот ведёт его по шагам: фото экрана с набранным `*#06#`, фото
   лицевой стороны, фото задней, видео. Хранятся они как `file_id`, то есть бесплатно,
   ровно так же, как медиа обычных сделок Оценки.
2. Точку сделки присылает сама программа: её `shop_id` — это тот же магазин Оценки, с тем
   же id. Бот точку не спрашивает вовсе (кнопки «выберите точку» больше нет).
   **Проверки руками** — кнопки, вибрация, Face ID, зарядка, SIM, герметик, детали
   Apple, чужие профили — сотрудник отмечает на экране программы, пока телефон клиента у
   него в руках, и они приезжают в посылке. Бот их тоже не спрашивает: кнопки в чате
   остались только для точек со старой сборкой, которая отметок ещё не присылает.
3. Приложение отправляет сделку JSON-файлом в рабочую группу Telegram: к файлу читаемая
   карточка (модель, память, IMEI, аккумулятор, детали, цена, клиент) и кнопка.
4. Оценщик нажимает кнопку. **Только нажатие и приносит боту посылку**: свои исходящие
   сообщения бот не видит, а в `callback_query` Telegram отдаёт сообщение целиком, вместе
   с файлом. Заодно это подтверждение — в карточке видно ровно то, что уйдёт в сделку.
5. Бот читает файл, добавляет видео и фото, присланные по тому же коду, создаёт сделку и
   передаёт её дальше: статус «Оценен» — карточкой с кнопками «Выкуп»/«Закрыть» оценщику
   в личку, «Ожидает оценку» — админам. Без этого сделка со статусом 1 не видна нигде.
   Создаётся она так:
   `devices` + `device_imeis`, клиент в `users` (staff_id 3), `status_id` по правилу самой
   Оценки. В ответ — номер сделки.

## Ограничения (не нарушать)

* По умолчанию на сервере только чтение: `SELECT`, логи, `grep`. Ничего не менять без
  явного подтверждения пользователя на каждое действие.
* Писать **только** в `pintel_ocenka_test`. Рабочую базу не трогать.
* Перед любым `UPDATE`/`DELETE`: сначала `SELECT` с числом задетых строк, потом бэкап,
  потом сама операция в транзакции с проверкой количества строк. Бэкап:
  `pg_dump -U postgres -Fc ИМЯ_БАЗЫ > ~/имя_$(date +%F_%H%M).dump`
* В `pintel_ocenka` удаление сделки (`devices`) каскадом сносит IMEI, реквизиты клиента и
  начисленные бонусы. Ничего не удалять.
* `pintel_ocenka` и `pintel` — **разные системы с разными наборами ролей**. Здесь речь
  только про `pintel_ocenka` (бот Оценки).
* Перезапуск `ocenka.service` (рабочий бот) рвёт все начатые диалоги продавцов — FSM живёт
  в памяти. Его перезапускать нельзя: только тестового бота. Если почему-то понадобится
  рабочий — лишь с разрешения и в окно 21:30–23:30 или 01:00–07:00 по Алматы.
* На сервере нет git: **перед правкой любого файла сделать копию** рядом
  (`cp main.py main.py.bak_$(date +%F_%H%M)`).
* Секреты (токен бота, пароли, ключи) не выводить в чат и не коммитить никуда.

## Шаг 1. Таблица обмена

Одна новая таблица, чужие не затрагиваются:

```
psql -U postgres -d pintel_ocenka_test -f kiosk_media.sql
```

Проверить: `\d kiosk_media` — должны быть `code UNIQUE`, `user_id`, `chat_id`, `shop_id`,
`video`, `photos`, `checks`, `done`, `device_id`. Колонки `point` быть не должно: имя точки
строкой не пишется с тех пор, как точку присылает программа своим `shop_id`. Если таблица
стояла раньше, её убирают руками — `ALTER TABLE kiosk_media DROP COLUMN IF EXISTS point;`.

К ним добавились три колонки для сделки: `parcel`, `parcel_at`, `parcel_error`. Через них
сделка с точки приходит в бота **без кнопки**: наш сервер кладёт посылку в `parcel`, бот
забирает её оттуда сам и создаёт сделку (почему так — ниже, Шаг 3в). Их `kiosk_media.sql`
добавляет тем же запуском.

**Если таблица уже стояла** (её ставили в прошлый раз), файл всё равно стоит прогнать: он
повторный запуск переживает, всё существующее пропускает. Колонка `checks` теперь нужна
только точкам со **старой** сборкой программы — тем, где проверки руками ещё спрашивает бот
кнопками; новая присылает отметки в посылке, и обработчик без этой колонки работает (строку
он читает целиком и `checks` берёт, если она есть). То есть порядок установки стал
свободным: можно сначала файлы, а SQL потом — приём медиа и создание сделок от этого не
встанут.

Скопировать `main.py`, потом добавить импорт и включение роутера **до** `router_start`:

```python
from handlers.kiosk_media import router_kiosk_media
...
dp.include_router(router_kiosk_media)   # ПЕРЕД dp.include_router(router_start)
```

Порядок важен: `router_start` ловит любой `/start` и заберёт нашу ссылку себе. Больше в
боте менять нечего — свои `/start` он обрабатывает как раньше, наш обработчик срабатывает
только на `/start p<КОД>`.

Перезапустить **только тестового** бота и посмотреть логи: при ошибке импорта он падает
сразу, и это видно в журнале юнита.

## Шаг 3б. Свой прайс у точки

Делается один раз, после установки файлов. Колонку добавляем руками: схему Оценка создаёт
через `create_all`, а он досоздаёт только таблицы.

```sql
ALTER TABLE shops ADD COLUMN IF NOT EXISTS price_url VARCHAR(300);
```

Чтобы колонка появлялась и на чистой базе, в модель `Shop` (`database/models.py`) добавлена
строка:

```python
    price_url: Mapped[Optional[str]] = mapped_column(String(300), nullable=True)
```

И в `utils/google_price.py` — две вставки. В `reset_price_cache`, чтобы кнопка админа
чистила и прайсы точек:

```python
    try:                                   # прайсы точек: handlers/kiosk_price.py
        from handlers.kiosk_price import сбросить_кэш
        сбросить_кэш()
    except Exception:                      # модуля нет — значит прайс один на всю сеть
        pass
```

И в начало `get_price_for_device`, сразу после проверки марки, модели и памяти:

```python
    # Прайс точки (shops.price_url). Своя вкладка есть, а строки в ней нет — автоцены у
    # сделки нет вовсе: цена из чужого списка хуже, чем ручная оценка.
    try:
        from handlers.kiosk_price import по_точке
    except ImportError:                    # модуль не поставлен — считаем по общему прайсу
        по_точке = None
    if по_точке is not None:
        try:
            свой, цена = await по_точке(device)
            if свой:
                return цена
        except Exception as e:             # noqa: BLE001
            logging.exception("Прайс точки недоступен (%s %s): %s", marka, model, e)
            return None
```

Ссылки в колонку вписывают руками, по одной на точку:

```sql
UPDATE shops SET price_url = 'https://docs.google.com/spreadsheets/d/<ключ>/edit#gid=<номер>'
 WHERE shop_name = '12/40';
```

Проверить: `SELECT shop_name, price_url FROM shops ORDER BY shop_name;` — и прогнать сделку
с точки, у которой ссылка стоит, на модели, которой в её вкладке нет: автоцены быть не
должно (`status_id` 2), а в журнале бота — строка «нет строки … — автоцены не будет».

## Шаг 3в. Сделка без кнопки

Так работает главный путь; шаг не требует правок — только понимания, что проверять.

Как было: программа на точке слала сделку файлом в чат Telegram, с карточкой и кнопкой
«Создать сделку в Оценке». Бот получал посылку ТОЛЬКО при нажатии: свои исходящие
сообщения он не видит, а в `callback_query` Telegram отдаёт сообщение целиком, вместе с
файлом. Значит, сделка зависела от чата — и однажды встала на этом совсем: боевой бот
ответил `Forbidden: bot was blocked by the user`, и сотрудник с телефоном клиента в руках
не мог сделать ничего.

Как теперь: касса отдаёт посылку нашему серверу (`POST /api/kiosk/media/<код>/parcel`), он
кладёт её в `kiosk_media.parcel`, а бот каждые две секунды смотрит, не появилось ли новой,
забирает её одним `UPDATE … SET parcel = NULL … RETURNING parcel` (этот же запрос — замок
от двойной сделки) и создаёт сделку тем же кодом, что и кнопка. Номер сделки сотрудник
видит на экране кассы и отдельным сообщением в том чате, откуда присылал фото и видео.
Не получилось — причина ложится в `parcel_error`, и её показывает экран кассы.

Карточка с кнопкой осталась запасным путём: её шлёт точка, у которой нет связи с нашим
сервером. Поэтому `ocenka_chat_id` в настройках точки по-прежнему нужен.

Что проверить: в журнале бота после перезапуска строка «слежу за посылками с точек».
Если вместо неё «посылки не посмотреть» — в базе нет новых колонок, вернуться к Шагу 1.

## Шаг 5. Проверка

1. Личный чат с ботом: `/start pTEST1`.
   * «Принимаю медиа для сделки…» — всё встало.
   * Обычное меню или тишина — роутер стоит после `router_start`.
   * «Этот код — для сотрудников Pintel» — обработчик работает, но `chat_id`
     проверяющего нет в `users` этой базы или его `staff_id` = 3.
2. Прислать боту три фото, потом видео — бот после каждого называет следующий шаг и
   принимает только то, что нужно на шаге: видео на шаге фото он не возьмёт и ответит
   «Нужно фото». Кнопок в сообщениях нет. Когда собрано всё, бот говорит: «Медиа собраны.
   Отметьте проверки руками на экране программы и отправьте оценку оттуда». Ни точку, ни
   проверки руками он не спрашивает — и то и другое приезжает в посылке.
3. Пункты проверок руками (кнопки, вибрация, Face ID, зарядка, связь, герметик, детали Apple,
   чужие профили) бот спрашивает кнопками **только** от точки со старой сборкой — см. п. 6.
   Экран, касание, камеры, динамик и микрофон не спрашиваются вовсе: их прогоняет сам
   телефон клиента на странице теста из киоска, и результат приезжает в посылке.
4. `SELECT code, user_id, shop_id, video, photos, done, device_id FROM kiosk_media ORDER BY id DESC LIMIT 5;`
   — строка с кодом TEST1, `file_id` видео и проставленной точкой.
5. Сквозная проверка — вместе с точкой: на кассе нажимают «Отправить в Оценку», и через
   пару секунд на её экране появляется номер сделки, а сотруднику приходит строка
   «✅ Сделка № … · цена · оценил …». Кнопку нажимать не нужно — её больше нет в этом
   пути. Проверить, что сделка **открывается** в Оценке (для этого и нужно видео:
   карточку она открывает через `InputMediaVideo(device.video_phone)` без проверки на
   пусто). Без точки то же самое проверяется руками:
   `UPDATE kiosk_media SET parcel = '<JSON посылки>', parcel_at = now() WHERE code = 'TEST1';`
   — через пару секунд `parcel` пуст, а `device_id` проставлен.
5б. Запасной путь (карточка с кнопкой) — для точек без связи с сервером: приложение
   присылает карточку в чат, оценщик нажимает «Создать сделку в Оценке», бот отвечает
   номером. Этот путь должен работать по-прежнему.
6. Отдельно проверить шлюз и путь для старой сборки: прислать карточку, в посылке которой
   нет `ручная_диагностика` (это и есть точка со старой программой), и нажать кнопку. Бот
   обязан отказать («Не хватает: проверки руками …») и прислать пункты кнопками в личку
   тому, кто сдавал медиа; после отметок (⬜ → ✅ → ❌, счётчик на «Готово» уменьшается)
   кнопка создаёт сделку. Если колонки `checks` в базе нет, бот вместо кнопок скажет, что
   отметки некуда записать и надо обновить программу на точке, — это ожидаемо.
7. И что отметка ❌ снимает автоцену: прислать посылку, где один пункт отмечен «не
   работает», создать сделку и посмотреть `SELECT status_id, phone_status, comment_ocenka
   FROM devices ORDER BY id DESC LIMIT 1;` — должно быть `status_id` 2, состояние
   «Присутствует дефект» (а по пункту «Детали Apple» — «Ранее был в ремонте») и строка
   «Ручная диагностика … НЕ РАБОТАЕТ: …».
8. Отдельно: посылка **без** теста на телефоне (её пришлёт точка со старой программой) должна
   создать сделку, а не упасть в отказ — но со `status_id` 2 и строкой «Теста на телефоне не
   было» в комментарии. Это и есть страховка на порядок установки: сборка уезжает на точки
   сама, а эти файлы ставят руками.

При любой ошибке бот пишет причину в тот же чат — молча он не отказывает. Если в чате
`❌ Сделка … не создалась: …`, прислать этот текст.
